# Archivage DARFT — 4 septembre 2026

DARFT est conservé comme projet autonome dans ce dépôt GitHub, mais son backend est retiré du projet Supabase partagé `Wikignose` afin de libérer l’architecture pour d’autres applications.

## Ce qui est conservé

- le frontend complet du prototype ;
- la doctrine produit et le système de sélection ;
- l’architecture technique ;
- les migrations Supabase `001_darft_core.sql` et `002_darft_project_cockpit.sql` ;
- la fonction Edge `submit-artwork` présente dans le dépôt ;
- l’état de pilotage au moment de l’archivage dans `supabase/archive/2026-09-04_project_state.sql`.

Le backend partagé contenait :

- 0 profil DARFT ;

- 0 image de candidature ;
- 0 entrée d’historique de statut ;
- 18 tâches de pilotage ;

- 0 objet dans le bucket Storage `darft-submission-images`.

Les 18 tâches et la décision de journal sont sauvegardées dans le snapshot SQL d’archive.

## Restaurer DARFT plus tard

Créer ou choisir un projet Supabase, puis :

1. appliquer `supabase/migrations/001_darft_core.sql` ;
2. appliquer `supabase/migrations/002_darft_project_cockpit.sql` ;
3. exécuter `supabase/archive/2026-09-04_project_state.sql` ;
4. redéployer `supabase/functions/submit-artwork` si nécessaire ;
5. reconnecter `assets/supabase-config.js` au nouveau projet ;
6. recréer les comptes d’administration nécessaires dans Supabase Auth et les profils DARFT associés.

Le retrait du backend partagé ne signifie donc pas la suppression du projet DARFT : le dépôt reste son archive de référence et son point de redémarrage.
